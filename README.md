# Мой перенос на Omarchy / Arch x86_64

Репозиторий содержит только установщик. Личные данные — в зашифрованных
release assets приватного репозитория. Ключ никогда не загружается в GitHub.
Игры, Codex и Claude не устанавливаются и их профили не копируются.
Названия собственных проектов с Claude в имени сохраняются как обычные проекты.

## Сейчас на Debian

1. Закрой Firefox, IDEA, Throne и pgAdmin перед окончательной копией.
2. Запусти в обычном терминале (скрипты запрашивают sudo там, где он нужен):

```bash
cd ~/omarchy-setup && bash prepare.sh
```

Если Docker не запущен, запусти его и повтори экспорт. Работающие контейнеры
нужно сначала штатно остановить; скрипт сам их не останавливает.
Экспорт PostgreSQL временно запускает остановленные Debian-кластеры и возвращает
их в прежнее состояние. Локальные Docker volumes сохраняются только при
остановленных контейнерах. Bind mounts вне проектов архивируются отдельно.
Внешние volume-драйверы требуют отдельного экспорта.

`private/migration.key` скопируй в менеджер паролей или на ДРУГОЙ носитель.
Не сохраняй единственную копию ключа на SSD, который собираешься стереть,
или на установочную флешку. Без него архив не восстановить.
Дождись завершения загрузки всех частей в GitHub release migration-v1.
Убедись, что можешь открыть приватный репозиторий и release из другого устройства.

Для предварительной копии только пользовательских данных:
`python3 export-private.py`. Она проверяется расшифровкой, но её публикация
заблокирована до экспорта системных БД/Docker.

## Флешка Omarchy (СТИРАЕТ флешку Debian)

```bash
cd ~/omarchy-setup && python3 flash-usb.py
```

Скрипт разрешает запись только на USB UDisk 16 ГБ с серийным номером
2601241108580572837513. Имя /dev/sda не зашито: устройство ищется по серийному
номеру и дополнительно проверяется. Скачивается стабильный x86 ISO по ссылке
с https://omarchy.org/; SHA256 берётся с официального ISO-сервера.
После записи выполняется побайтовая проверка. SSD исключён.
`python3 flash-usb.py --dry-run` только проверяет устройство.

## На новой Omarchy — одна команда после входа в GitHub

Если репозиторий приватный, сначала войди: `gh auth login -p https -w`.

```bash
gh repo clone Enotik-G/omarchy-setup && cd omarchy-setup && bash bootstrap.sh --restore
```

Будет нужен sudo и путь к отдельно сохранённому ключу. Установка рассчитана
на Omarchy/Arch x86_64; это не универсальный установщик для Debian/Windows.
Приватный архив скачивается автоматически из GitHub release.

## Что устанавливается

Java 25, Maven, Gradle, Node 24 LTS, npm, Python, uv, pipx, C/C++ toolchain,
ESP build prerequisites, Docker + Compose/Buildx, PostgreSQL, Neovim, tmux,
Git/GitHub CLI, SSH, поиск/архиваторы, Firefox, Blender, Godot.
IntelliJ IDEA — актуальный официальный архив JetBrains с проверкой SHA256;
Ultimate требует действующую лицензию. pgAdmin — Python 3.12 venv через uv
(локальный веб-интерфейс, не Debian desktop runtime), запуск `pgadmin4`.
Throne — `yay -S --needed throne-bin`, если yay установлен. AUR может запросить
подтверждение. Prettier, tree-sitter-cli и corepack ставятся в ~/.local.

Полные локальные проекты (включая .git/.env и незакоммиченные файлы), Firefox,
SSH/GPG, Git/GitHub, IDEA/Neovim, pgAdmin, Throne, ESP и локальные JDK,
личный Granat/Moss и Aseprite сохраняются в зашифрованном архиве.
Node_modules/venv в проектах сохраняются как часть снимка, но после смены ОС
их нужно пересоздать по lock-файлам: бинарные зависимости могут не работать.
Ссылки за пределы архива при распаковке пропускаются и перечисляются в
skipped-external-symlinks.json; это также касается путей Python из старых venv.
Системный Java находится в /usr/lib/jvm/java-25-openjdk; старые пути SDK в IDEA
при необходимости нужно выбрать заново. Для ESP SDK переустанови Python-env
через штатный install.sh из сохранённого esp-idf.

## Восстановление и ограничения

Файлы новой системы не перезаписываются: конфликтующие версии из копии лежат
в ~/.local/share/enotik-setup/ДАТА/conflicts. При переносе Firefox до первого
запуска профиль обычно находится автоматически; иначе `firefox -P`.
Cookies/пароли/профиль копируются, но сайты могут потребовать повторный вход,
а ключница — старый пароль. Не обещаем автоматическую авторизацию везде.
Настройки терминала из Debian сохранены в reference, поскольку там есть токены
и Debian-специфичные пути; они не заменяют конфигурацию Omarchy.

SQL и Docker backup лежат в ~/.local/share/enotik-setup/ДАТА/system.
На свежей системе один кластер PostgreSQL и отсутствующие Docker volumes
восстанавливаются автоматически. Существующие базы и тома не перезаписываются: 
скрипт остановится и оставит дампы для ручного импорта. Несколько PostgreSQL
кластеров и внешние bind mounts требуют ручного разбора.
Далее — инструкция для ручного восстановления при необходимости.
Для совершенно новой PostgreSQL: инициализируй кластер `sudo -u postgres
initdb -D /var/lib/postgres/data`, запусти `sudo systemctl enable --now postgresql`.
Из pg_dumpall уже существует роль postgres, поэтому один такой конфликт ожидаем;
восстановление всего SQL через psql требует анализа вывода и проверки БД.
Предпочтительно раздельно восстановить роли и базы по инструкции PostgreSQL:
https://www.postgresql.org/docs/current/backup-dump.html

Docker: metadata в docker-volumes.json, каждый volume — отдельный tar.gz.
Создай том с прежним именем (`sudo docker volume create ИМЯ`), распакуй его
архив с sudo в Mountpoint из `sudo docker volume inspect ИМЯ`, затем подними
соответствующий compose-проект. Не распаковывай bind-mount archive поверх /
без проверки списка путей. Images скачиваются заново по compose-файлам.

## Проверка

`bash check.sh` — синтаксис и проверки поведения без установки пакетов,
без записи USB и без публикации. Полноценный прогон установщика на Omarchy
в этой Debian-сессии не выполнен. Списки пакетов проверяются pacman перед установкой.
